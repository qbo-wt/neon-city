# Neon City v0.1 — Plan d'implémentation

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal :** une tranche jouable du rogue-lite : planque → district de 8 salles → mini-boss → retour à la planque, avec implants, jauge de psychose et arbre de compétences sauvegardé.

**Architecture :** la logique de jeu pure (stats, psychose, parade, arbre, sauvegarde, génération de run) vit dans `src/core/` sans import de Phaser. Elle est testée avec Vitest. Les scènes et les entités Phaser (`src/scenes/`, `src/entities/`) ne font qu'appeler ce cœur. Le contenu (implants, ennemis, nœuds, salles) est décrit en données typées dans `src/data/`.

**Tech Stack :** Phaser 4.2.1, TypeScript 7, Vite 8, Vitest 5 (versions vérifiées via npm le 2026-11-06). **L'API de Phaser 4 diffère de Phaser 3 : consulter Context7 (`phaser`) avant d'écrire du code Phaser.**

**Spec :** [docs/design.md](../../design.md)

## Global Constraints

- Univers original : aucun nom, personnage ou asset de Cyberpunk 2077. Ville = « Neon City ».
- Aucun fichier image : tous les sprites sont générés par le code (`src/gfx/`).
- Résolution interne 480×270, `pixelArt: true`, mise à l'échelle FIT.
- Contrôles : ZQSD **et** flèches pour bouger, Espace = dash, clic gauche = attaque vers le curseur, clic droit = parade (menu contextuel du navigateur désactivé).
- Palette : nuit `#0b0820`, cyan `#00f0ff`, magenta `#ff2a6d`, jaune `#f5e663`, blanc `#e8e8ff`.
- Tous les réglages chiffrés sont dans `src/config.ts` (aucun chiffre magique dans les scènes).
- Le `dt` est borné à 50 ms par frame (un changement d'onglet ne doit pas téléporter ni tuer le joueur).
- Lancement : `npm run dev` · vérification : `npm test` + `npm run build` (inclut `tsc --noEmit`).

## Review Focus

1. **Sauvegarde corrompue ou ancienne** dans localStorage → on charge la sauvegarde par défaut, sans planter (test dans la Task 4).
2. **Changement d'onglet ou gros lag** → le `dt` borné empêche la psychose de bondir et le joueur de traverser les murs (test dans la Task 3 : `tickPsychosis` avec un dt énorme borné).
3. **Ennemis qui apparaissent dans un mur ou sur le joueur** → les points d'apparition sont tirés parmi les cases libres, à au moins 64 px du joueur (test dans la Task 5).
4. **Psychose qui tue hors combat** → la perte de vie ne s'applique que dans la RunScene, en salle active, jamais pendant une transition ni à la planque (Task 8 : drapeau `roomActive`).
5. **Achat d'un nœud sans assez de crédits ou sans son prérequis** → refusé, l'état reste inchangé (test dans la Task 2).

### Task 2 : Stats, implants, arbre de compétences

**Files :**
- Create : `src/core/types.ts`, `src/core/stats.ts`, `src/core/skillTree.ts`, `src/data/implants.ts`, `src/data/skillNodes.ts`
- Test : `tests/core/stats.test.ts`, `tests/core/skillTree.test.ts`

**Interfaces :**
- Produces :
  - `interface Stats { maxHp; damage; speed; dashCharges; critChance; psyResist /*0..0.9*/; creditMult; implantLoadMult }`
  - `interface Implant { id; name; description; load: number; modify: (s: Stats) => Stats }`
  - `interface SkillNode { id; name; description; cost: number; requires?: string; modify: (s: Stats) => Stats }`
  - `baseStats(): Stats` · `computeStats(implants: Implant[], ownedNodes: string[]): Stats` (applique d'abord les nœuds, puis les implants) · `totalLoad(implants, stats): number` (= somme des charges × `implantLoadMult`)
  - `canBuy(nodeId, owned: string[], credits): boolean` · `buyNode(nodeId, owned, credits): { owned: string[]; credits: number }` (lève une erreur si achat impossible)
  - `IMPLANTS: Implant[]` (8 implants) · `SKILL_NODES: SkillNode[]` (8 nœuds)

- [ ] **Step 1 :** tests. `computeStats([], [])` égale `baseStats()`. Un implant « +5 dégâts » donne `damage === 15`. Un nœud « +20 vie » combiné à un implant « +20 vie » donne `maxHp === 140`. `totalLoad` avec un nœud qui fixe `implantLoadMult` à 0.8 et des charges de 10+5 donne 12. `buyNode` sans assez de crédits ou sans le prérequis lève une erreur et ne modifie pas les tableaux d'entrée. Un achat valide retire le coût et ajoute l'id. Chaque `IMPLANTS[i].load > 0`. Tous les ids sont uniques.
- [ ] **Step 2 :** `npm test` → FAIL.
- [ ] **Step 3 :** implémenter les modules. Les noms sont originaux. Implants : lames de bras, jambes renforcées (+1 charge de dash), optique de visée (+crit), dermo-blindage (+vie max), réflexes boostés (+vitesse), coprocesseur neural (+20 % de dégâts), pompe à adrénaline (+vitesse et +dégâts, avec une charge élevée), plaque sous-cutanée (+vie max, avec une charge faible). Nœuds : 2 branches (corps : vie / dash · esprit : résistance psy / réduction de la charge / crédits), avec des prérequis en chaîne.
- [ ] **Step 4 :** `npm test` → PASS. Commit `feat: stats, implants and skill tree core`.

### Task 3 : Psychose et parade

**Files :**
- Create : `src/core/psychosis.ts`, `src/core/combat.ts`
- Test : `tests/core/psychosis.test.ts`, `tests/core/combat.test.ts`

**Interfaces :**
- Produces :
  - `type PsyTier = 'stable' | 'glitch' | 'drain' | 'crisis'` · `psyTier(v): PsyTier` (<50 stable, <75 glitch, <100 drain, 100 crisis)
  - `tickPsychosis(v, load, dtMs, resist): number` (+ `load × PSY_RATE_PER_LOAD × (1−resist) × dtSec`, dt borné à `MAX_DT_MS`, résultat borné à [0,100])
  - `psyOnKill(v, resist): number` · `applyBlocker(v, amount): number`
  - `hpDrainPerSec(tier): number` (0, 0, `PSY_DRAIN_SLOW`, `PSY_DRAIN_FAST`)
  - `crisisMultipliers(tier): { damage: number; speed: number }` (1/1 hors crise)
  - `resolveParry(parryStartMs, hitAtMs): 'parried' | 'hit'` (parée si `0 ≤ hit − start ≤ PARRY_WINDOW_MS`)
  - `computeHitDamage(stats, { countered: boolean; tier: PsyTier; roll: number }): { amount: number; crit: boolean }` (crit si `roll < critChance` ⇒ ×2 ; contre ⇒ ×`COUNTER_MULT` ; crise ⇒ ×`CRISIS_DAMAGE_MULT`)

- [ ] **Step 1 :** tests. `psyTier` aux bornes 49.9/50/74.9/75/99.9/100. Une charge nulle ne fait pas monter la jauge. `tickPsychosis(0, 10, 100000, 0)` est égal à `tickPsychosis(0, 10, 50, 0)` (dt borné). La jauge reste ≤ 100. Une résistance de 0.5 divise la hausse par deux. `applyBlocker` ne descend pas sous 0. Parade : un coup reçu à +0 ms et à +150 ms est paré, à +151 ms et à −1 ms il ne l'est pas. Dégâts : 10 de base, contré et en crise ⇒ 30 ; avec `roll` sous `critChance` ⇒ ×2.
- [ ] **Step 2 :** FAIL → **Step 3 :** implémenter → **Step 4 :** PASS. Commit `feat: psychosis and parry rules`.
